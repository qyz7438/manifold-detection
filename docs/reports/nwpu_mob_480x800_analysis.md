# NWPU MobileNetV3 480×800 分辨率验证分析

## 1. 实验配置

- 模型：Faster R-CNN MobileNetV3-Large-320-FPN
- 数据集：NWPU VHR-10
- 输入尺寸：min_size=480, max_size=800（batch=8）
- 训练：12 epochs，3 seeds（42 / 2024 / 999）
- fpn_sm 配置：latent=64/hidden=128, init_alpha=0.01, 无坐标

## 2. 结果

## 3. 关键发现

### 3.1 增大分辨率确实能提升 baseline
- 320×480 baseline：AP50 0.496，AP75 0.146
- **480×800 baseline：AP50 0.734，AP75 0.298**
- AP75 提升约 **104%**，确认小目标场景分辨率是主要瓶颈。

### 3.2 fpn_sm 在高分辨率下更不稳定
- seed999 在第 1 个 epoch 就出现 `loss=NaN`，alpha0 也变为 NaN。
- 原因：输入增大后，FPN 特征能量更强，init_alpha=0.01 + lr=0.024 的组合在特定初始化下导致梯度爆炸。

### 3.3 排除发散种子后，fpn_sm 仍有收益
- 成功种子（42、2024）均值：AP50 0.765，AP75 0.346，ECE 0.038。
- 与 480×800 baseline（AP50 0.734，AP75 0.298）相比：
  - AP50 +4.2%
  - AP75 +16.1%
  - ECE 从 0.061 降至 0.038（校准更好）

### 3.4 模块压缩强度进一步增大
- 480×800 fpn_sm 成功种子 alpha0 ≈ 0.64，eff_rel_delta0 ≈ 0.62。
- 远高于 320×480 的 alpha0≈0.37。
- 说明输入分辨率越高，模块学到的压缩越强，但仍能带来 AP75 提升（只要不发散）。

## 4. 结论

**“小目标密集场景需要增加输入尺寸”这一假设成立。**

- 分辨率从 320×480 提升到 480×800 后，baseline AP75 翻倍。
- fpn_sm 在 480×800 上能进一步提升 AP75（成功种子 +16%），但 **init_alpha=0.01 对 480×800 不稳定**。

## 5. 下一步建议

1. **调低 init_alpha 或学习率**：对 480×800 MobileNetV3，尝试 init_alpha=0.005 或 lr=0.012，避免 seed999 式的发散。
2. **补 seed999 重跑**：用更保守的参数重新跑 seed999，确认稳定性。
3. **VOC 上同样使用更大输入**：如果 VOC 实验开始，MobileNetV3 分支也应使用 480×800 而非默认 320/480。
4. **梯度裁剪**：在训练脚本中加入 `nn.utils.clip_grad_norm_`，提高大输入+fpn_sm 的稳定性。
